# Домашнее задание: `double.asm`

Прочитать число, удвоить и напечатать результат. Работа только с системными
вызовами Linux x86-64, без libc и без функций.

## Контракт

- **Вход:** одна строка со стандартного входа: целое число `0…99`, цифры и
  перевод строки. Вход гарантированно корректный: без пробелов, знака и мусора.
- **Выход:** ровно `Result: N` и перевод строки, где `N = 2 × вход`.
  Без ведущих нулей: `0 → Result: 0`, `21 → Result: 42`, `99 → Result: 198`.
- **Код завершения:** `0` при успехе.

| Вход | Выход |
|---:|---|
| `0` | `Result: 0` |
| `1` | `Result: 2` |
| `7` | `Result: 14` |
| `21` | `Result: 42` |
| `49` | `Result: 98` |
| `99` | `Result: 198` |

## Ограничения

- Платформа: Linux x86-64, NASM, Intel-синтаксис, freestanding `_start`.
- Только syscalls: `read` (0), `write` (1), `exit` (60). Никаких `printf`,
  `atoi` и библиотечных вызовов.
- Код линейный: без `call`/`ret`, `push`/`pop` и отдельных функций.
- Один `read` в буфер 32 байта. В учебных прогонах предполагаем, что он
  успешно получает всю строку с LF. В общем случае размер буфера не
  гарантирует полного чтения.
- Цифры писать в буфер с конца: деление даёт младшую цифру первой.
- Отрицательные числа, переполнение, мусор на входе и повтор короткого
  чтения и частичной записи не требуются.

## Сборка и запуск

```sh
mkdir -p build
nasm -f elf64 double.asm -o build/double.o
ld -o build/double build/double.o
printf '21\n' | ./build/double
```

Ожидаемо: `Result: 42`. Для проверки кода завершения сразу после запуска:

```sh
./build/double <<< '21'
echo $?
```

## Этапы

Делайте по одному этапу и проверяйте каждый.

1. **read и эхо.** Прочитайте строку и выведите её обратно тем же числом
   байтов, что вернул `read`. Ввод `21` → вывод `21`.
2. **Разбор.** Превратите цифры в число и завершитесь с этим кодом:
   `mov edi, eax; mov eax, 60; syscall`. `echo $?` для ввода `21` даёт `21`.
3. **Удвоение.** Добавьте `add eax, eax` перед выходом: код для `21` — `42`.
4. **Цифры.** Напечатайте только число без префикса: для `21` — `42`,
   для `0` — `0`, для `49` — `98`. Проверьте обратный порядок цифр.
5. **Формат.** Добавьте `Result: `, LF и проверьте все шесть строк из таблицы.
   Вход `99` проверяет результат из трёх цифр.

## Отчёт по бинарю

Соберите свою программу и ответьте на три вопроса. Указывайте значения из
**своей** сборки, а не из примера.

1. **Префикс.** В какой секции лежат байты `Result: `? Назовите файловое
   смещение и восемь байтов в hex. Подсказка: `strings -a -t x build/double`
   и `objdump -s -j .rodata build/double`.
2. **Деление.** Найдите в `objdump -d -M intel build/double` блок перевода
   числа в цифры. Назовите адрес первой инструкции блока, байты `xor edx,edx`
   и `div`, а также объясните, зачем EDX обнуляется перед каждым делением.
3. **Буфер.** Что находится в `.bss`? Назовите имя, размер и адрес буфера
   ввода: адрес — по `nm build/double`, размер — по `resb` в исходнике,
   секция — по `readelf -S`. У обычной метки NASM поле Size в `readelf -s`
   может быть нулевым: размер не записан в таблицу символов. Почему байтов
   буфера нет в файле? Найдите в дизассемблере
   инструкцию, которая загружает адрес этого буфера.
4. **Бонус.** У программы несколько `syscall`. Почему их байты одинаковы
   (`0F 05`), а действия разные? Что определяет выбор вызова?

## Критерии

- 50% — программа выдаёт ровно ожидаемое для шести входов из таблицы,
  без лишних байтов в stdout;
- 30% — отчёт по бинарю совпадает с собственной сборкой;
- 20% — код читаемый, границы обработаны: `0`, LF в конце, нет ведущих нулей.

## Подсказки

- `movzx ecx, byte [rsi]` — прочитать один байт по адресу.
- `sub ecx, '0'` — превратить код цифры в значение.
- `imul eax, eax, 10` — сдвинуть накопленное на десятичный разряд.
- `xor edx, edx` перед `div ebx` — обязательное обнуление старшей половины.
- `add dl, '0'` — превратить остаток в код цифры.
- `lea rdi, [rel numbuf + 4]` — указатель на конец буфера; цифры идут назад.
- Длина для `write` — число цифр плюс один байт LF.
- `syscall` изменяет `RCX` и `R11`. До печати префикса сохраните адрес
  цифр в `R8`, а их длину с LF — в `R9`, как предложено в скелете.
