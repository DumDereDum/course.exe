# Мини-практика SCA — 10 минут

Цель: самостоятельно запустить Trivy, разобрать CVE-2022-37434, изменить зависимость проекта, пересоздать lock-файл, получить новый SBOM и повторить анализ.

## Что проверяем

project/conanfile.txt задаёт зависимость C/C++-проекта zlib/1.2.11. project/conan.lock создан настоящим Conan 2.21.0. В этой мини-практике проверяется разрешённый граф зависимостей перед сборкой. Библиотека не устанавливается, бинарник не собирается. Для выпуска далее нужны установка зависимостей по lock-файлу, сборка и тесты продукта. Ручная правка SBOM или удаление находки из отчёта не меняет зависимость.

## Подготовка до занятия

Установите и запустите Docker. Скачайте и распакуйте архив в отдельную папку. Базовый образ rbpo-sast должен быть собран по Dockerfile практики SAST. Здесь Dockerfile дополняет его Trivy 0.73.0 и Conan 2.21.0; он не меняет Dockerfile предыдущей практики.

На компьютере из распакованной папки:

```sh
docker build -t rbpo-sca .
docker run --rm -it \
  -v "$PWD:/work" rbpo-sca
```

Внутри контейнера с доступом к интернету:

```sh
trivy --version
conan --version
conan profile detect
conan download zlib/1.2.11 \
  --only-recipe -r=conancenter
conan download zlib/1.2.13 \
  --only-recipe -r=conancenter
trivy image --download-db-only
```

Рецепты Conan и база Trivy сохраняются в .conan-cache/ и .trivy-cache/ подключённой папки; они доступны после выхода и нового docker run. Скачивается только рецепт Conan, а не бинарник библиотеки. Эта подготовка не входит в 10 минут занятия. Убедитесь, что все команды завершились успешно. На компьютерах с Bash/zsh путь $PWD работает как показано; для другой оболочки подключите абсолютный путь к папке.

Подготовленный Conan lock-файл можно пересоздать из кеша:

```sh
conan lock create project -nr \
  --lockfile="" \
  --lockfile-out=project/conan.lock
```

-nr запрещает обращение к удалённым репозиториям. Если рецепт отсутствует в кеше, сначала завершите подготовку при доступном интернете. Флаг --lockfile="" не подхватывает старый lock-файл и исключает сохранение прежних версий в новом графе.

## Во время практики — 8 минут

Все команды ниже выполняются из /work в контейнере. Файлы редактируйте на компьютере.

1. **2 минуты:** получите исходный отчёт прямой командой:

```sh
mkdir -p reports
trivy fs --scanners vuln \
  --skip-db-update --format json \
  --output reports/before.json project
```

Откройте reports/before.json в редакторе. Найдите CVE-2022-37434, пакет, InstalledVersion, FixedVersion и источник advisory. Сверьте условие использования inflateGetHeader() с записью CVE. Граф сам по себе не позволяет подтвердить применимость к выполняемому продукту; запишите статус «исследуется» и недостающие сведения.

2. **2 минуты:** выберите версию исправления выбранной CVE по отчёту и release notes. Измените зависимость в project/conanfile.txt. Используемые здесь 1.2.11 и 1.2.13 — исторический пример, а не рекомендация версии для нового проекта.

3. **2 минуты:** заново создайте lock-файл и повторите анализ:

```sh
conan lock create project -nr \
  --lockfile="" \
  --lockfile-out=project/conan.lock
trivy fs --scanners vuln \
  --skip-db-update --format json \
  --output reports/after.json project
```

Не редактируйте conan.lock вручную. Обе проверки используют одну уже скачанную базу. --skip-db-update сохраняет условия сравнения; свежесть базы зависит от подготовки до занятия.

4. **2 минуты:** получите новый состав и проверьте результат:

```sh
trivy fs --format cyclonedx \
  --output reports/bom.json project
```

В новом lock-файле и SBOM должна быть выбранная версия zlib, а в успешно полученном after.json — не должно быть CVE-2022-37434 для zlib. Пакет нельзя потерять из анализа. Остальные CVE остаются для отдельного разбора: их число не является критерием этой практики. Пустой набор findings без подтверждения состава не считается успехом.

Сохраните conanfile.txt, conan.lock, reports/before.json, reports/after.json, reports/bom.json и заметку с решением. Последние 2 минуты блока — разбор на слайде 26.

## Параметры и пределы

--scanners vuln включает только проверку уязвимостей; --format json и --output задают формат и файл. fs читает зависимости проекта, sbom сканирует уже готовую ведомость. Ни одна команда не спрятана в скрипте-обёртке.

Сразу после каждой команды можно проверить echo $?. Для данных команд ожидается 0, но у Trivy код 0 по умолчанию допускает находки. Ошибка инструмента, нераспознанный lock-файл или отсутствие zlib в составе не считаются успешным анализом.

Для генерации SBOM Trivy использует lock-файл. Лицензии Conan требуют дополнительных данных из кеша: в этой практике проверка лицензий не выполняется. SBOM перед сборкой не доказывает состав выпускного бинарника.

Проверка выполнена локально на macOS arm64; версия базы сохранённого результата — 11.08.2026. Ubuntu-контейнер пока не проверен: Docker daemon на машине подготовки не запущен. Резервные отчёты в материалах лекции предназначены для разбора и не заменяют собственный запуск.
