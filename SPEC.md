# Архитектура сборника

Документ для разработки движка. Автору одного слайда нужен только SLIDE_GUIDE.md.

## Продуктовые решения

- Библиотека преподавателя организована по темам, независимо от преподаваемого курса.
- Главная — простой терминал на всё окно: заголовок, путь папки, список и мигающий курсор.
  Корневые папки: assembler и common; Git находится в common/git. Без больших иллюстраций,
  вложенных рамок и боковой панели описания.
- Слайды — спокойный тёмный холст, светлый текст, зелёный акцент, минимум декора.
- Объяснение даёт преподаватель. На экране — вопрос, схема, пример, вывод.
- Демонстрации заранее спланированы, воспроизводимы, имеют шаг назад и сброс.
- Новый слайд создаётся с малым контекстом: руководство + brief + один шаблон/контракт виджета.

## Автономность

Просмотр: index.html через file://; работает также на обычном статическом хостинге.
HTML5, CSS, vanilla JS с defer. Нет npm, fetch для содержания, ES-модулей, шрифтов из сети,
базы данных и обязательного сервера. Сборка: Python 3.10+, стандартная библиотека.
Внешние ссылки и iframe — отдельные действия; iframe создаётся по кнопке.
Docker не нужен для библиотеки. Будущие стенды живут отдельно и имеют локальный резерв на слайде.

## Данные и сборка

`src/lectures/<раздел>/<лекция>/meta.txt` — 3 строки: название / описание / дата.
`brief.md` — короткий план для автора, не попадает в сборку.
`slides/NN.html` — внутренний HTML с комментарием type. Номера сортируются численно.
`src/catalog.json` — дерево topics: name, description, sections, lectures, folders.
sections включает лекции соответствующего раздела исходников, lectures — отдельные пути.
folders задаёт вложенные темы; имя папки меню не обязано совпадать с разделом исходников.
`_kit` — служебная мастерская для автора, открывается напрямую и не входит в главное меню.
В assembler пока одна лекция, в common/git — только титульник будущей лекции.

build.py читает источники, tools/content.py проверяет фрагменты. Сначала проверяются все
источники и ссылки, затем записываются результаты. --check ничего не пишет;
--lecture ограничивает запись одной лекцией, каталог обновляется всегда.
--new копирует выбранный шаблон в следующий номер без перезаписи существующих файлов.
Выход: `lectures/<раздел>/<лекция>.html` и `index.html`; оба коммитятся.
Оболочки: templates/lecture.html, home.html; авторские фрагменты — templates/slides/.
`@ASSETS@` во фрагменте заменяется на относительный путь ../../assets.

## Вёрстка

Главная занимает всю ширину и высоту окна (100% × 100dvh), без max-width и внешней рамки.
Шапка и подсказки остаются видимыми; длинный список прокручивается внутри свободной области.
Лекция вписана в 16:9; логический холст 1600×900, размеры в cqw/cqh от .deck.
Шапка 7.5cqh, нижняя панель 8cqh, отдельная .stage между ними.
Слайды центрируются внутри сцены с безопасными отступами, содержимое не прокручивается.
Не использовать минимальные пиксельные размеры, нарушающие масштабирование холста.
Переполнение лечится содержимым или новым слайдом, не уменьшением шрифта.
Помощь — dialog вне масштабируемого холста; может прокручиваться.

CSS: site.css — токены и общие элементы; home.css — каталог;
deck.css — геометрия и навигация; components.css — словарь авторских компонентов.
Изображения и крупные SVG — отдельные файлы. Не добавлять картинки в виде base64.

## Навигация и состояния

home.js читает встроенное дерево каталога. Клик выбирает, двойной клик или Enter открывает.
Возврат к родителю восстанавливает его выбранный элемент. Пустая папка корректно отображается.
Мигает только курсор заголовка, список не мигает. prefers-reduced-motion отключает эффекты.

deck.js отвечает за навигацию, hash слайда, inert неактивных слайдов, панели, клавиши.
Стрелки и PageUp/PageDown всегда листают; пробел вызывает шаг, Shift+пробел — назад,
R — сброс. На обычном слайде пробел листает. Интерактив сохраняется при переходе между
слайдами, перезагрузка начинает его заново. Hash сохраняет только номер слайда.
Клавиши не перехватываются в полях, диалогах; Space/Enter не перехватываются на кнопках и ссылках.
Не открывать панели или внешние инструменты автоматически.

## Виджеты

Классические скрипты регистрируют фабрики в window.LectureWidgets.
Фабрика получает элемент data-widget и возвращает `{step, back, reset}`.
Состояние локально для экземпляра; один главный виджет на слайд.
Не обращаться к другим слайдам, не использовать eval, не выполнять строки как команды.
Кнопки локальны. API для автора документируется отдельно в docs/widgets/.

Текущие виджеты: sequence (HTML-состояния), registers (упрощённая арифметическая модель),
endian (раскладка 32-битного числа). Их код не нужен модели при генерации слайда.
resources.js отвечает за копирование и явную загрузку iframe. Отдельные большие сцены — assets/demos/.

## Расширение

Сначала проверить, можно ли выразить задачу кадрами sequence, SVG или отдельной сценой.
Если нет: добавить независимый файл виджета, подключение в оболочке, короткий контракт,
шаблон, рабочий пример в мастерской, валидацию данных и проверку поведения.
Не выращивать универсальный симулятор в одном deck.js. Не менять общий API молча.

## Качество и ограничения

Обязательные размеры: 1600×900 и 1280×720. Проверка клавиатурой и мышью,
назад/сброс/конец, сохранение состояния при навигации, локальные ссылки, file://.
Проверки сборщика: типы, размер ≤6 КБ, один заголовок, ID, ссылки, вставки, данные виджетов.
Смысл текста, точность модели, переполнение и доступность внешнего сервиса проверяются отдельно.
Заметки notes скрыты, хранятся для подготовки в исходниках и не вызываются при показе.
Телефон не целевой экран презентации. PDF/печать и редактирование через веб-интерфейс не реализованы.
Не считать Compiler Explorer подготовленным, пока не закреплены конкретная версия и Share-ссылка.
