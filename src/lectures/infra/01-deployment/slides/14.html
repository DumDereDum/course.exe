Процесс выполняет ядро Ubuntu в ВМ demo; второго ядра нет.

Связь: на слайде 13 образ был основой для нескольких контейнеров. Теперь проследить один запуск backend:v1 внутри ВМ demo, где установлен Docker Engine.

Сказать: docker CLI обращается к API демона dockerd. Демон готовит образ и конфигурацию контейнера и передаёт управление жизненным циклом containerd. В обычной конфигурации containerd использует runc для создания и запуска процесса по спецификации OCI. Ядро гостевой Ubuntu предоставляет файловую систему, пространства имён, cgroups и выполнение инструкций. docker run совмещает создание контейнера и его запуск; когда главный процесс завершается, контейнер останавливается.

Граница схемы: стрелки показывают роли компонентов, а не точное дерево процессов или последовательность системных вызовов. backend:v1 — условное имя будущего образа, реальный стенд ещё не готов. В нашем стенде Docker-хост — гостевая Ubuntu в ВМ demo, а не физический KVM-хост.

Спросить: какое ядро выполняет backend? Ответ: ядро Ubuntu внутри ВМ demo.

Источники: Docker Engine; containerd и runc.
