DOCKER / 05 · ограничения ядра

Ядро ограничивает ресурсы и действия.

Один процесс · три механизма
backend
  ├─ cgroups       → CPU, память, процессы
  ├─ capabilities  → привилегированные действия
  └─ seccomp       → системные вызовы
Пример лимитов

--memory=256m · --cpus=1 · --pids-limit=64 — значения задают явно.

Ограничения применяет ядро Ubuntu в ВМ demo, общее для контейнеров.

Связь: namespaces на предыдущем слайде меняют видимые ресурсы. Здесь показать другие механизмы: сколько ресурсов процессу доступно и какие действия он может выполнять.

Сказать: cgroups учитывают процессы и могут ограничить память, долю CPU и число процессов. Конкретные значения лимитов появляются после явной настройки; один только факт принадлежности контейнера cgroup не означает ограничение памяти в 256 МБ. Capabilities делят полномочия root на отдельные права, и Docker по умолчанию оставляет ограниченный набор. Seccomp фильтрует системные вызовы, через которые процесс обращается к ядру. Это параллельные механизмы, не три последовательных шага.

Граница модели: контейнеры используют общее ядро Ubuntu в ВМ demo. Права, монтирования и режимы запуска меняют степень изоляции; например, --privileged существенно расширяет возможности контейнера. Значение --cpus=1 задаёт квоту CPU, а не закрепляет за контейнером отдельный физический процессор.

Спросить: какой механизм ограничит память, а какой проверит допустимость системного вызова? Ответ: cgroups и seccomp соответственно.

Источники: cgroup v2; безопасность Docker Engine; seccomp в Docker.
