DOCKER / 02 · образ и контейнер

Образ задаёт основу.
Контейнер получает состояние.

Образ backend:v1

Слои только для чтения: среда выполнения, библиотеки и код.

В настройках — рабочий каталог и команда запуска.

Два контейнера из образа
backend:v1
   ├──→ A: процесс + слой записи
   └──→ B: процесс + слой записи

Остановленный контейнер можно запустить снова.

docker build создаёт образ; docker run создаёт и запускает новый контейнер.

Сказать: образ — подготовленная основа: файлы и настройки запуска. Из одного образа можно создать несколько контейнеров. Их слои образа общие и доступны только для чтения, а изменения файлов каждый экземпляр пишет в свой слой. При запуске у каждого появляется свой главный процесс. Остановленный контейнер остаётся существовать до удаления.

Команды: docker build создаёт образ; docker run создаёт и запускает новый контейнер. backend:v1 на схеме — условное имя будущего образа, а не уже подготовленный стенд.

Спросить: если контейнер A создаст файл в своём слое, увидит ли его контейнер B? Ответ: нет, без общего тома или другого механизма обмена данными.
