DOCKER / 13 · управление Compose

Имена сервисов и состояние проекта

ВМ demo · сохранённый пример
$ docker compose up -d
Состояние после команды
web       running
backend   running
web → backend:8000
сеть: <проект>_default
ВМ demo · сохранённый пример
$ docker compose stop
Состояние после команды
web       stopped
backend   stopped
контейнеры остаются
сеть остаётся
ВМ demo · сохранённый пример
$ docker compose down
Состояние после команды
контейнеров нет
сети проекта нет
образы остаются
именованные тома остаются

stop сохраняет контейнеры; down удаляет их вместе с сетью.

Сценарий: перед каждой командой спросить, что останется после неё. Это подготовленные состояния, команды на слайде не выполняются. Пробел — дальше, Shift + пробел — назад, R — сброс.

Сказать: сервисы Compose в одной сети находят друг друга по имени. Адрес backend:8000 используется внутри web при настроенном прокси; IP контейнера может меняться. up -d запускает сервисы в фоне. stop не удаляет контейнеры, их записываемые слои и сеть: их можно снова запустить через compose start. down удаляет контейнеры с их записываемыми слоями и сеть, но по умолчанию сохраняет образы и именованные тома. down -v удалит и тома проекта.

Граница: пример предполагает уже подготовленные образы demo-web:1 и demo-backend:1 из предыдущего слайда; реального стенда пока нет. Имя сети зависит от имени проекта.

Спросить: после down новый контейнер web получит прежний записываемый слой? Ответ: нет; постоянные данные следует хранить в томе или внешнем хранилище.

Источники: сеть Compose; stop; down.
