DOCKER / 12 · Compose

Compose описывает запуск нескольких сервисов

compose.yaml
services:
  web:
    image: demo-web:1
    ports: ["80:80"]
  backend:
    image: demo-backend:1
После docker compose up -d
ВМ demo:80 → web:80
web → backend:8000
сеть: <проект>_default

Оба сервиса входят в общую сеть; имя backend доступно из web.

Compose создаёт контейнеры и сеть из файла; наружу опубликован только web.

Сказать: Compose читает compose.yaml и создаёт сервисы как контейнеры одного проекта. Без явного networks он создаёт сеть default; сервисы находят друг друга по имени. ports публикует порт 80 web на порту 80 Ubuntu внутри ВМ demo. У backend нет ports: его порт 8000 доступен web в общей сети, если приложение слушает на этом порту.

Граница: Compose не настраивает прокси автоматически: образ web должен содержать конфигурацию обращения к http://backend:8000. Имена образов учебные; готовых web и backend в стенде пока нет. -d запускает сервисы в фоне.

Спросить: сможет ли клиент снаружи ВМ обратиться к backend:8000 напрямую? Ответ: нет, его порт не опубликован; клиент идёт через web при настроенном прокси и сетевом доступе к ВМ.

Источники: модель Compose; сеть Compose.
