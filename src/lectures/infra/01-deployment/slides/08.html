Гостевая ВМещё один уровень
sudo apt update
sudo apt install qemu-system-x86
ls -l /dev/kvm
sudo qemu-system-x86_64 -accel kvm \
  -m 512 -display none \
  -monitor stdio

Ubuntu x86-64 внутри WSL2. В мониторе QEMU: info kvm, затем quit. Диск не подключён.

Сказать: WSL2 уже работает в виртуальной машине. Если Windows передаёт ей аппаратные возможности виртуализации, модуль KVM внутри Linux-ядра WSL2 может выполнять код ещё одной гостевой ВМ. QEMU запускается как процесс внутри дистрибутива и обращается к /dev/kvm.

Показ: команды рассчитаны на Ubuntu x86-64 внутри WSL2. Установить QEMU, проверить наличие /dev/kvm, затем запустить пробную ВМ с явным ускорителем KVM. sudo использован только для этой короткой проверки, чтобы не зависеть от членства пользователя в группе kvm. Диск не подключён: гостевая ОС не загружается, но QEMU создаёт ВМ и запускает виртуальный CPU. В мониторе QEMU команда info kvm должна показать активный KVM; quit завершает процесс. Если ускоритель недоступен, QEMU выдаст ошибку вместо незаметного перехода на программную эмуляцию.

Граница проверки: наличие /dev/kvm само по себе недостаточно. Параметр nestedVirtualization в .wslconfig влияет на доступность вложенной виртуализации, но её работоспособность зависит также от Windows, CPU, ядра WSL и политик компьютера. Реальный запуск на WSL2 здесь не выполнялся.

Спросить: сколько уровней ВМ здесь показано? Ответ: два: среда WSL2 и гостевая ВМ, которую запускают QEMU и KVM внутри неё.

Переход: после проверки KVM можно подключить к ВМ установочный ISO или готовый образ диска. Конкретная среда для практического стенда ещё не проверена.
