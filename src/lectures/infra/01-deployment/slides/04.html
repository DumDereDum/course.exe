vCPU получает время
на реальном процессоре.

vCPU гостявиден гостевой ОС
→
Поток QEMUодин на vCPU
→
KVM_RUNвход в гостевой режим
→
Физический CPUвыполняет код гостя
Кто распределяет время

Linux планирует потоки QEMU вместе с остальными процессами хоста.

vCPU — не отдельный чип: его код исполняется на общем физическом CPU.

Сказать: гостевая ОС считает, что у неё есть собственный процессор. В обычной конфигурации QEMU каждому vCPU соответствует поток хоста. Поток вызывает KVM_RUN, и гостевые инструкции выполняются физическим CPU с аппаратной поддержкой виртуализации. Планировщик Linux решает, когда поток получает время.

Пример: если ВМ получила два vCPU, это не резервирует для неё два физических ядра: потоки конкурируют за время с другими задачами хоста.

Спросить: сможет ли Linux на хосте выполнять другие процессы, пока работает ВМ? Ответ: да; он планирует потоки ВМ вместе с остальными.
