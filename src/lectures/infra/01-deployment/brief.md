# KVM, Docker и Ansible — воспроизводимое развёртывание

Размещение в каталоге: common/infrastructure. Раздел исходников: infra.
Аудитория: третий курс; знакомы с программированием, архитектурой компьютера и ОС.
Формат: 80 минут, сопровождение живого объяснения. Рабочий план: 47 слайдов.
Текущий статус: реализованы титул 01, согласованный блок 02–11 о QEMU, KVM,
установке гостевой ОС, WSL2 и первых шагах Ansible, а также слайды
12–20 о Docker, образе, запуске, изоляции, сборке и сканировании Trivy, 23–25 о Compose и проверке работы, а также 29 о пути запроса в сети Docker. Блок 02–11 посвящён только виртуальным машинам;
контейнеры и сравнение с ними в нём не вводить. Остальной план и лабораторная
ещё не реализованы.
Следующие слайды сначала подробно описывать текстом и обсуждать с автором;
редактировать после согласования.

Сквозной пример: готовое приложение из web и backend. Web отдаёт страницу и
проксирует запросы API. Backend доступен web по сети Docker, его порт не публикуется.
Linux-ВМ работает на KVM; Docker Engine и Compose запускаются внутри гостя.
Ansible настраивает локальный KVM-хост, создаёт ВМ, затем настраивает гостя по SSH.
Первый доступ: готовый cloud image и минимальный cloud-init с публичным SSH-ключом.
Установка с ISO на слайде 06 объясняет обычный путь; в практическом стенде
используется образ с уже установленной ОС.

Среда студента: собственный Linux или WSL2. WSL и вложенная виртуализация
объясняются на двух слайдах; подготовка среды и устранение проблем —
самостоятельная работа. Для KVM в WSL2 нужна работающая вложенная виртуализация.
Точную среду, образ и версии требуется проверить
перед подготовкой реального стенда. Готовых web/backend и стенда пока нет.

Сети — основная линия объяснения: внешняя сеть → сеть ВМ → сеть Docker.
Пример HTTP: KVM-хост:8080 → ВМ:80 → web:80 → backend:8000.
Пример SSH: KVM-хост:2222 → ВМ:22. Проброс не меняет порт sshd в госте.
Смена внешнего порта не заменяет ключи и ограничения входа.
«Снаружи» означает внешнего по отношению к гостю клиента; необходимость проверки
с другого компьютера локальной сети ещё нужно уточнить при подготовке лабораторной.
