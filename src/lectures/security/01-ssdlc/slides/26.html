Меняем зависимость проекта.
Lock-файл и SBOM получаем заново.

Прямые команды · повторная проверка
conan lock create project -nr \
  --lockfile="" \
  --lockfile-out=project/conan.lock
trivy fs --scanners vuln \
  --skip-db-update --format json \
  --output reports/after.json project
Получить новый SBOM
trivy fs --format cyclonedx \
  --output reports/bom.json \
  project

Сохранённые проверки ↗

Критерий завершения
  • zlib 1.2.13 учтена.
  • Выбранной CVE нет.
  • Оба отчёта и новый
    SBOM сохранены.

Кадр 1: 1.2.13 — историческое исправление CVE-2022-37434, не рекомендация версии для нового проекта. Изменение в conanfile.txt должно сопровождаться новым разрешением зависимостей.

Кадр 2: Conan 2.21.0 создаёт граф из подготовленного кеша, --lockfile="" не использует старый lock-файл. Без этого старые версии могут остаться в объединённом lock-файле. Команда не устанавливает и не собирает библиотеку. После успешного разрешения повторяют Trivy на project с той же базой.

Кадр 3: CycloneDX генерируется Trivy по обновлённому lock-файлу. Проверить, что пакет не исчез из состава, нужная версия есть в Packages отчёта и components SBOM, выбранная CVE отсутствует. Ошибка анализа или потерянный компонент не считаются исправлением.

Сохранённый запуск: macOS arm64, Trivy 0.73.0, Conan 2.21.0, база 11.08.2026. До: zlib 1.2.11, две находки, включая выбранную CVE. После: zlib 1.2.13, находок в этом снимке нет. Все команды завершились с кодом 0. Полные JSON, lock-файлы и параметры сохранены в assets/examples/security/sca-lab/.

Граница: актуальная база может дать другие находки; критерий относится к выбранной CVE. Безопасность продукта этим не доказана. Для выпуска далее установить зависимости по lock-файлу, собрать, проверить состав артефакта и пройти функциональные и регрессионные тесты. Применимость остальных находок рассматривается отдельно.
