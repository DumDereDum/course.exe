Показ: первые два кадра — подготовка заранее, третий оставить на 8 минут работы. Далее слайд 26 — двухминутный разбор. Преподаватель команды не запускает; это инструкция студенту.

Среда: Docker должен работать, rbpo-sast уже собран. Dockerfile добавляет Trivy 0.73.0 из официального образа, Python venv и Conan 2.21.0. -v подключает папку к /work. Кеши сохраняются в .conan-cache и .trivy-cache этой папки. Файлы редактируют на компьютере. Проверить версии инструментов по README.

Подготовка: profile detect определяет настройки среды. download --only-recipe получает только рецепты двух версий с указанного remote; бинарники не устанавливаются. Базу Trivy загрузить до занятия. Все шаги должны завершиться успешно; это время не входит в практику.

Задание: анализировать project/conan.lock, полученный Conan, найти пакет, версии, источник и условие CVE. По одному графу применимость к выполняемому продукту не подтверждается. Выбрать исправление, изменить project/conanfile.txt, пересоздать lock-файл, повторить Trivy и получить SBOM. Команды следующих шагов находятся в README архива.

Параметры: fs проверяет зависимости проекта; --scanners vuln оставляет проверку уязвимостей; --skip-db-update использует подготовленную базу; --format json и --output задают отчёт. До и после сравниваются на одной базе. Успешный код Trivy по умолчанию допускает находки.

Граница: проверяется граф перед сборкой, не состав бинарника. Установка, сборка и тесты — дальнейшие действия. Практика проверена локально; контейнерная сборка не проверена, Docker daemon не запущен. Резервные отчёты в assets/examples/security/sca-lab/ не заменяют собственный запуск.
