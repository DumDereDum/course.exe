→
Мутацияизменяем данные

Обратная связьпокрытие и сбои

Новое покрытие → вход в очередь.
Ошибка или зависание → отдельный разбор.

AFL++ меняет входы, ASan проверяет память при запуске.

Сказать: корпус — небольшой набор исходных файлов, например корректные варианты входного формата. AFL++ меняет их и исполняет цель. Если вход даёт полезную новую информацию о покрытии, он сохраняется для следующих мутаций. Цикл повторяется; это не просто случайные байты.

Цель: программа должна реально читать изменяемый вход. Для большой системы выделяют harness — небольшой адаптер к нужной функции. Передача файла через @@ и чтение stdin — варианты организации входа, а не разные виды анализа. Для учебной практики нужен быстрый воспроизводимый запуск.

Результаты: queue содержит интересные входы; crashes — входы со сбоями, hangs — зависания. Обычный отказ на некорректных данных не должен превращаться в аварийный сигнал. Сохранённый сбой воспроизводят, сокращают вход с сохранением ошибки и разбирают причину.

Граница: рост покрытия не равен проверке всех состояний и не доказывает безопасность. Быстрый запуск без входа в нужную функцию бесполезен. Dictionaries, persistent mode, CMPLOG и режимы для готовых бинарников оставлены за пределами этого десятиминутного блока.
