06 / SAST · путь к дефекту

Трасса объясняет
путь к ошибке

Пример пути · повторное освобождение памяти
Выделениеmalloc
→
Освобождениеfree(p)
→
Условиеretry ≠ 0
→
Повторное freefree(p)

Проверяем условия пути, а не только отмеченную строку.

Сказать: путь в отчёте показывает, откуда возникло проблемное состояние. В нашем сохранённом примере память выделена, указатель проверен на NULL, затем память освобождена. При retry != 0 та же память освобождается повторно. Это Double Free; классификация будет показана на слайде 09.

Происхождение: схема сокращает настоящую трассу Clang Static Analyzer из assets/examples/security/sast/report.txt. Источник отчёта — examples/rbpo/sast-report/ownership.c. Пропущен безопасный шаг проверки указателя на NULL, который есть в полном отчёте. Схема не является текущим запуском программы.

Анализ путей: path-sensitive анализ различает состояния на разных ветках; межпроцедурный анализ учитывает вызовы функций. Конкретный инструмент может использовать символическое исполнение и другие методы, а его модели имеют ограничения.

Потоки данных: taint analysis отслеживает данные от недоверенного источника source до чувствительной операции sink и учитывает применённые проверки. Это другой пример статического анализа, а не объяснение показанного Double Free.

Действие: при разборе проверяем выполнимость условий и то, действительно ли ресурс уже освобождён. Причина может находиться раньше отмеченной строки или в другой функции.

Источник: https://clang.llvm.org/docs/ClangStaticAnalyzer.html. Время: 2 минуты.
