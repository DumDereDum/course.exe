# Лекция 2 — условия и циклы

Аудитория: студенты после первой лекции по x86-64, Linux и NASM, знакомые с условиями и циклами на C.
Цель: связать сравнения, флаги и переходы с выбором ветки и повторением участка программы.
Платформа: x86-64, Linux, NASM; Intel-синтаксис.
Формат: сопровождение живого объяснения преподавателя, 80 минут.
Статус: созданы слайды 01–16, полные программы, инструкция Docker/ELF и разбор Hex Editor. Практика на 80 минут ещё не оформлена. Запуск примеров подтверждён автором; автоматическая проверка браузером остаётся непроверенной: file:// ограничен инструментом. Дата занятия не назначена. Лекция начинается сразу с RIP; вступление и повторение смысла if/while исключены.

Начать сразу с RIP: код хранится в памяти, RIP содержит адрес следующей исполняемой инструкции; при последовательном выполнении адрес увеличивается на длину инструкции в байтах. Затем метки и jmp как способ изменить дальнейший адрес исполнения. Смысл условий и циклов на C аудитории уже известен.

Слайд 01 показывает фрагмент с условным начальным адресом 0x401000: mov rax, rbx (3 байта), add rax, rcx (3), sub rax, 1 (4). Последний кадр указывает на продолжение по 0x40100A; содержимое продолжения не задано. Это подготовленная модель на границе между инструкциями, не настоящий процессор и не модель конвейера. Значения рабочих регистров не моделируются.

Слайд 02: mov eax, 10; jmp skip; add rax, 5; skip: sub rax, 2. Подсветка следует только выполняемым инструкциям; таблица адресов, машинных байтов, меток и инструкций остаётся неподвижной. RIP меняется 0x401000 → 0x401005 → 0x40100B → 0x40100F, RAX — неизвестно → 10 → 10 → 8. Запись в EAX обнуляет верхние 32 бита RAX. Метка размещена у адреса sub, отдельной строки или байтов для неё нет. Адреса, размеры и байты инструкций проверены локальной сборкой NASM.

Слайд 03: mov eax, 7; mov ebx, 7; cmp eax, ebx; mov ebx, 3; cmp eax, ebx. Первый шаг объединяет два подготовительных MOV; остальные выполняют по одной инструкции. После первой CMP ZF=1, после MOV EBX=3 флаги сохраняются, после второй CMP ZF=0. Операнды при CMP не изменяются. CF/SF/OF в обоих сравнениях равны 0. Машинные байты и адреса проверены NASM и дизассемблером.

Слайд 04: CMP; JE/JNE yes; MOV ECX,0; JMP done; yes: MOV ECX,1; done. EAX и EBX задаются полями, изменение выбора сбрасывает показ. Подсветка идёт по фактически выбранному маршруту; байт 74/75 и его подпись меняются вместе с командой. При равенстве JE срабатывает, JNE пропускается; при различии наоборот. Сброс сохраняет выбранные числа. Модель и кодировки проверяются отдельно; другие флаги не показаны.

Слайд 05: TEST EAX,EAX для нуля или TEST EAX,1 для чётности, затем JZ и две ветки с ECX=0/1. AND не записывается в EAX; ZF соответствует нулю результата, CF/OF сброшены. Показаны младшие 8 из 32 бит, верхние 24 нулевые при диапазоне 0…255. Переключение режима меняет TEST с 2 на 5 байтов, адреса и подписи смещений. Кодировки проверены NASM. Ноль рассматривается как чётное число.

Слайд 06: EAX=0xFFFFFFFF и EBX=1 остаются неизменными во всех кадрах. Сначала раскрывается unsigned=4294967295 и ложное сравнение с 1, затем signed=−1 и истинное сравнение. Старший бит 31 выделен; дополнительный код объясняется устно. Значения в карточках — трактовки одного регистра, не независимые регистры. Далее — CMP с JL/JB.

Слайд 07: EAX=FFFFFFFF и EBX=00000001 зафиксированы. CMP даёт разность FFFFFFFE и ZF=0, CF=0, SF=1, OF=0. JL проверяет SF≠OF и срабатывает; JB проверяет CF=1 и пропускается. При смене команды показ возвращается к началу, CMP повторяет те же флаги. Выделяются только проверяемые флаги; байт 7C/72 и его описание меняются вместе с командой. Итог ECX=1 для JL, 0 для JB; EAX/EBX и флаги после CMP сохраняются.

На первых семи слайдах каждая пара hex-цифр (один байт) имеет подпись при наведении и фокусе. На 06 это содержимое регистра, на остальных — кодировки инструкций. На смене кадра или шага подсказка закрывается. SVG вставляются сборщиком; просмотр через file:// не требует fetch.

Каждая подпись содержит таблицу HEX/BIN: сверху две hex-цифры, снизу по четыре бита под каждой. Для B8 это B | 8 над 1011 | 1000; ведущие нули сохраняются. Ниже таблицы — описание назначения байта.

Слайд 08: справочная таблица после CMP EAX,EBX. Колонки signed и unsigned, строки <, ≤, >, ≥; JE/JNE общие. Строки раскрываются в три этапа без угадывания. Стандартные браузерные подписи команд содержат полные условия по флагам. Машинный код здесь не показан: размеры и смещения будут в конкретном IF/ELSE.

Слайд 09: CMP EAX,EBX; JL use_b; MOV ECX,EAX; JMP done; use_b: MOV ECX,EBX; done. Выбираются целые signed32, сравнение через SF≠OF; по умолчанию 7/3. Показываем также 3/7, 7/7 и −3/−7. Один MOV записывает максимум в ECX, другая ветка пропущена. Код C и выбранная ветка подсвечиваются вместе с машинным маршрутом. Байты всех пяти инструкций имеют HEX/BIN-подсказки.

Слайд 10: check: CMP EAX,EBX; JGE done; INC EAX; JMP check; done. Начальные 0/3 дают три итерации и EAX=3, значения 3/3 или 4/3 — сразу выход без тела. По одному шагу на инструкцию, флаги SF/OF меняются после CMP и INC, источник флагов подписан. Обратное смещение F8 трактуется как signed8 −8. После done показ останавливается.

Слайд 11: EAX до MOV неизвестен, ECX заранее равен 0. FOR устанавливает EAX=0 один раз, в теле добавляет 2 в ECX, затем увеличивает EAX. При границе 3 итог EAX=3, ECX=6; при 0 тело не выполняется, но инициализация выполняется. Возврат JMP на CMP по 401005 минует MOV по 401000; F5 — signed8 −11. C-части init/condition/body/update/exit подсвечиваются отдельно.

План продолжения: RIP, метки и jmp; cmp/test и флаги; условные переходы для знаковых и беззнаковых чисел; if/else; while/for; сумма 1…N; сборка и проверка полной программы. Массивы и функции оставлены для следующих лекций.
План практики (80 минут): проверка среды, модуль небольшого числа, сумма 1…N, НОД положительных чисел вычитанием, проверка результатов.

При создании слайдов использовать существующие шаблоны и виджеты; просмотр должен работать через file://.
