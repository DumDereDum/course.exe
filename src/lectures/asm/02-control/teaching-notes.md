# Последние слайды лекции 2

Формат: сначала объяснить пример, затем показать выполнение. Студенты уже знают
условия и циклы на C. На экран выводим связь переменных, инструкций, байтов и
состояния; подробности ниже предназначены преподавателю.

Лекция выросла до 28 слайдов (~120 минут): слайд 04 вводит логику условного
перехода, слайд 05 — каталог всех переходов с условиями по флагам, а перед
каждым интерактивным примером стоит разбор: две колонки C/NASM и вывод
с логикой перехода. Вложенные панели убраны, чтобы код помещался без уменьшения шрифта. Разборы короткие; при нехватке
времени их можно ужать, не трогая интерактивы.

## 04 — логика условного перехода, 4 минуты

Три роли: cmp/test выставляют флаги, условный переход проверяет условие и
выбирает адрес, байт 7x в короткой форме кодирует условие (74 je, 7C jl, 72 jb).
Следующий байт — signed8, −128…127; отсчёт от конца перехода.
В near-форме x86-64 используются 0F 8x и signed32. Формула
перехода читается вслух: «jl срабатывает, когда SF ≠ OF — знаковое первый
операнд меньше второго». Вопросы: mov флаги не меняет; inc/add между cmp и
переходом могут изменить нужные флаги. INC сохраняет CF; отслеживаем конкретный флаг.

## 05 — каталог переходов, 5 минут

Две колонки: со знаком (jl 7C, jle 7E, jg 7F, jge 7D) и без знака
(jb 72, jbe 76, ja 77, jae 73), снизу je 74 и jne 75 для равенства. Читать
строки по образцу: смысл — условие по флагам — байт. Правило выбора:
знаковые счётчики и значения с минусом — jl/jle/jg/jge; адреса, размеры,
биты — jb/jbe/ja/jae; равенство — всегда je/jne. Синонимы: je/jz, jne/jnz,
jc/jb. Дальше подробно показываем JE/JNE, JZ, JL/JB, JGE и JG; остальные строки — справочник.

## Разборы 06, 08, 11, 13, 15, 17, 19 — по 2–3 минуты каждый

Общая схема разбора: слева C и соответствие переменных регистрам, справа
NASM, снизу условие перехода и роль JMP. Метки объединены со строками
инструкций, done показана явно. Накопители value/sum начинаются с нуля;
их загрузка в ECX находится до интерактивного фрагмента. Пройти блоки
слева направо, задать вопросы из заметок слайда, затем перейти к интерактиву.

| Разбор | Мост к интерактиву |
|---|---|
| 06 · je/jne | ZF по cmp; ветка «не равны» за переходом, jmp обходит чужую ветку |
| 08 · test/jz | AND без записи; ноль результата — ZF=1; jz = je |
| 11 · jl/jb | cmp одна; jl читает SF/OF, jb — CF; данные со слайда 10 |
| 13 · max | переход проверяет противоположное a<b и ведёт в else |
| 15 · while | выход jge — противоположное условию продолжения; jmp к метке check |
| 17 · for | mov-инициализация до метки; возврат минует её |
| 19 · sum | граница i≤N → выход jg; ZF=1 при i=N включает последнее слагаемое |

## 20 — сумма от 1 до N, 7 минут

EAX — очередное слагаемое, EBX — N, ECX — накопитель. ECX заранее равен 0;
первый MOV устанавливает EAX=1. В полной программе из архива инициализация
ECX тоже присутствует. На интерактивном слайде N=0…5, начальное 4.

```c
for (int i = 1; i <= N; i++) {
    sum += i;
}
```

Полностью разобрать первую итерацию: CMP готовит флаги, JG проверяет выход,
ADD прибавляет EAX к ECX, INC выбирает следующее число, JMP возвращает к CMP.
После ADD сумма уже изменилась, а счётчик ещё прежний. После INC счётчик
изменился, а сумма сохранилась. Последующие итерации пройти быстрее.

Для N=4 история EAX: 1→2→3→4→5; история ECX: 0→1→3→6→10. Конечный счётчик
равен 5: это первое число за границей. Результат находится в ECX, не в EAX.

При равенстве i=N ZF=1, поэтому JG не срабатывает и последнее число входит
в сумму. Выход: ZF=0 и SF=OF. ADD/INC меняют флаги; новый CMP готовит их
для следующего JG. При N=0 после MOV и первой проверки сразу выходим,
сумма 0, EAX=1.

Показать подсказку F6: signed8 −10, отсчёт от конца JMP, возврат к 401005.
Подвести к ошибке границы на следующем слайде.

## 21 — границы, трактовка и источник флагов, 6 минут

Три кадра: слева ошибка, справа исправление. Фрагменты принимаются ассемблером;
проблема проявляется в поведении. Это подготовленные примеры, угадывание не требуется.

### Кадр 1. Потерян последний элемент

Сумма пока 6, EAX=EBX=4. Сравнение даёт ZF=1, SF=OF=0.

```asm
; ошибка                 ; исправление
cmp eax, ebx             cmp eax, ebx
jge done                 jg done
```

JGE выходит при равенстве и теряет последнее слагаемое; получается 6.
JG оставляет равенство в теле; после добавления 4 получается 10.
Байты перехода меняются 7D→7F. Граница в C — i≤N; противоположное условие
выхода — i>N. Контрольные случаи: пустой диапазон, один элемент, последний элемент.

### Кадр 2. Выбрана другая трактовка числа

Знаковый максимум −1 и 1. EAX=FFFFFFFF, EBX=1, CF=0, SF=1, OF=0.

```asm
; ошибка                 ; исправление
cmp eax, ebx             cmp eax, ebx
jb use_b                 jl use_b
```

JB читает CF и пропускается; программа выбирает −1. JL читает SF/OF и
выбирает 1. Байты 72→7C. В регистре нет отметки signed; трактовку задаёт
выбранный переход. На экране используется структура веток максимума из слайда 14.

### Кадр 3. CMP больше не источник текущего ZF

EAX=EBX=7, ECX=0.

```asm
; ошибка                 ; исправление
cmp eax, ebx             inc ecx
inc ecx                  cmp eax, ebx
je equal                 je equal
```

Слева ZF=1 после CMP, затем ZF=0 после INC. JE пропускается, хотя операнды
сравнения равны. Справа последнее обновление — CMP, поэтому JE срабатывает.
Обе версии оставляют ECX=1; исправление меняет источник флагов перед переходом.
Перестановка безопасна здесь, потому что ECX не участвует в сравнении.

Не формулировать правило как запрет любой инструкции между CMP и Jcc:
MOV сохраняет флаги. Нужно проследить именно инструкции, меняющие нужные флаги.
Условный переход читает текущее состояние, а не историю сравнения.

Общий вывод: сначала условие выхода, затем трактовка чисел, затем источник флагов.

## 22 — четыре полных примера, 3 минуты

На слайде 22 — четыре карточки примеров и ссылка на следующий слайд.
Слайд 23 содержит отдельную пошаговую инструкцию работы из репозитория.
Полная студенческая инструкция: `examples/asm/README.md`.
Архив: `assets/examples/asm/control-examples.zip`. Исходники доступны отдельно.

| Программа | Что показывает | Ожидаемый код |
|---|---|---:|
| max.asm | CMP/JL и две ветки, максимум 7 и 3 | 7 |
| abs.asm | CMP/JGE и NEG, модуль −7 | 7 |
| sum.asm | Счётчик и накопитель, сумма 1…4 | 10 |
| for.asm | Инициализация отдельно, три итерации с +2 | 6 |

Все программы freestanding: `_start`, `.text`, регистры, алгоритм, `syscall`.
В конце результат копируется в EDI, в EAX записывается 60 и выполняется
sys_exit. Объяснить, почему сумму надо сохранить до изменения EAX.
Результат показываем через `$?`; это младшие 8 бит, примеры выбраны небольшими.

## 23 — запуск из репозитория и чтение ELF, 6 минут

Пять шагов: открыть проект в VS Code → Docker → сборка и запуск →
дизассемблер → ELF и сырые байты.

### Подготовить до занятия

Запустить Docker Desktop/Engine, скачать Debian и установить NASM/binutils.
Интернет-загрузку не включать в время показа. Открыть корень репозитория
в VS Code. В терминале компьютера сначала перейти в папку исходников:

Windows PowerShell:

```powershell
Set-Location .\examples\asm
Get-ChildItem
```

macOS:

```sh
cd examples/asm
ls
```

Затем на обеих ОС выполнить одну и ту же команду:

```sh
docker run --name asm-examples --platform linux/amd64 -it --mount "type=bind,source=${PWD},target=/work" -w /work debian:bookworm-slim bash
```

Текущая папка уже examples/asm: дополнительный путь к PWD не добавляем.
--mount подключает её как /work; -w выбирает рабочую папку. На Windows
Docker Desktop использует Linux-контейнеры и WSL 2. Дальше команды идут
внутри Linux, включая NASM/ld и echo "$?". Повторный вход с компьютера:
`docker start -ai asm-examples`.

### Показать на занятии

1. Открыть sum.asm, отметить инициализацию EBX/ECX/EAX и блок завершения.
2. NASM создаёт .o, ld создаёт ELF. Запустить sum и сразу echo "$?": ожидаем 10.
3. Студенты вручную собирают, компонуют и запускают каждый пример; ожидаемые коды 7,7,10,6.
4. Через objdump -d -M intel найти CMP/JG/ADD/INC/JMP и SYSCall.
5. Прочитать одну строку: адрес в памяти → байты → инструкция.
6. Через readelf -h и -S найти архитектуру, точку входа, .text, Addr/Off/Size.
7. Через od посмотреть первые 64 байта файла: сигнатура 7F454C46 относится к ELF.
8. Через objcopy извлечь .text и через ndisasm -b64 разобрать сырой код.

Команды полностью приведены в README, на слайде есть копирование. Вывод на
слайде не имитирует настоящий терминал: команды выполняет преподаватель.

Файловое смещение в od, адрес секции в ELF и смещение в извлечённой .text
могут быть разными. NDISASM по умолчанию начинает с 0; для тех же адресов,
что в objdump, задают -o с Addr секции. Весь ELF содержит заголовки и таблицы,
поэтому для NDISASM берём извлечённую кодовую секцию.

Символы помогают найти `_start` и метки; комментарии исходника не восстанавливаются.
Дизассемблер может выбрать синоним JNL вместо JGE — машинный код тот же.

## 24 — Hex Editor, 4 минуты

Четыре подготовленных шага: открыть собранный abs, читать смещения и колонки,
сопоставить семь инструкций с objdump, прочитать −7 как Int32 little-endian

Затем повторить в настоящем VS Code. Смещение .text у abs — 0x1000; у других
примеров читать колонку Off через readelf -S.

## 25 — поиск команд в байтах примеров, 3–4 минуты

Четыре карточки с ожидаемыми подписями байтов (сборка nasm -f elf64 + ld
без PIE, код .text с файлового смещения 0x1000):

| Пример | Искать | Что это |
|---|---|---|
| max | 39 D8 7C 04 по 0x100A; 89 C1 по 0x100E; 89 D9 по 0x1012 | cmp + jl; ветка a; ветка b |
| abs | 83 F8 00 7D 02 по 0x1005; F9 FF FF FF по 0x1001 | cmp с нулём + обход neg; число −7 |
| sum | 7F 06 по 0x1011; EB F6 по 0x1017 | jg — цикл включает N; возврат к проверке |
| for | 83 C1 02 по 0x1013; 7D 07 по 0x1011 | тело add ecx, 2; выход jge |

Пройти карточки и назвать строку исходника за каждой подписью. Студенты
повторяют поиск в собранном файле: Go To Offset 0x1000 → сопоставить с
objdump -d -M intel. Вопросы: почему 89 C1 и 89 D9 различаются (ModR/M
выбирает источник ветки); чем подпись sum отличается от for (7F против 7D,
01 C1 против 83 C1 02 — граница и тело читаются из байтов).

## 26 — текст в stdout, 5 минут

Пятый полный исходник text.asm включён в архив. Два кадра: сначала строка
в .rodata и write, затем ручная сборка и сохранённый результат реального запуска.
Строка `Hello from the ASM lab` содержит 22 ASCII-символа; db 10 добавляет LF,
итого 23 байта. В показанном фрагменте директива db разделена на две строки;
в полном исходнике строка и 10 находятся в одной db, байты одинаковы.

RAX=1 выбирает Linux x86-64 write, RDI=1 — stdout, RSI — адрес через LEA,
RDX=23 — количество байтов. Нулевой байт не нужен. Затем CMP/JNE проверяют
RAX=23; ошибка или короткая запись дают exit=1, успех — exit=0.
Повтора частичной записи нет. Отличить текст на экране от кода завершения.
Docker: stdout точно `Hello from the ASM lab\n`, 23 байта, exit=0;
с закрытым stdout exit=1. На слайде не интерактивный терминал, а сохранённый вывод.

## 27 — ASCII, 3 минуты

Фрагмент таблицы: 00 NUL, 0A LF, 20 пробел, 30…39 цифры, 41…5A заглавные,
61…7A строчные, 7F DEL. ASCII использует семь бит, 00…7F; печатные знаки
с пробелом — 20…7E. Полная таблица: https://datatracker.ietf.org/doc/html/rfc20.
Указать систему счисления: 20 HEX = 32 DEC = 0010 0000 BIN.
Символ «0» — байт 30, нулевой байт — 00. UTF-8 сохраняет ASCII для этих
латинских символов, но кириллица использует несколько байтов.

## 28 — поиск по пробелам, 5 минут

Приём автора: искать HEX-байт 20. Через несколько байтов снова 20?
Посмотреть соседние символы в Decoded Text. Читаемые слова и пробелы —
признак возможного текста. Интервалы не обязаны повторяться точно;
один байт 20 также может быть частью инструкции, числа или случайных данных.
Текст может не содержать пробелов, быть сжатым или в другой кодировке.
Не путать байт 20 с поиском двух текстовых символов «20» (32 30).

В text строка в .rodata: файловое смещение 0x2000, адрес 0x402000,
длина 0x17. Пробелы по 0x2005, 0x200A, 0x200E, 0x2012; расстояния 5, 4, 4.
На втором кадре все 23 байта сгруппированы по восемь для читаемости;
в редакторе по умолчанию 16 байт на строку, смещения сохраняются.
Последний 0A — LF. Строка в .rodata является данными, не кодом.

Проверить Linux-командами strings -a -t x, readelf -S и objdump -s -j .rodata.
strings сканирует весь файл и даёт файловые смещения в hex. Выбрать нужную
строку среди остальных результатов, включая имена символов/секций;
наличие строки не доказывает, что она выводится программой.
В своей сборке читать Off из readelf, затем Go To Offset в Hex Editor.
Слайды — сохранённый резерв; команды и байты проверены в Docker,
живой поиск в расширении VS Code отдельно не проверялся.
