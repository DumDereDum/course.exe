# Последние слайды лекции 2

Формат: сначала объяснить пример, затем показать выполнение. Студенты уже знают
условия и циклы на C. На экран выводим связь переменных, инструкций, байтов и
состояния; подробности ниже предназначены преподавателю.

## 12 — сумма от 1 до N, 7 минут

EAX — очередное слагаемое, EBX — N, ECX — накопитель. ECX заранее равен 0;
первый MOV устанавливает EAX=1. В полной программе из архива инициализация
ECX тоже присутствует. На интерактивном слайде N=0…5, начальное 4.

```c
for (int i = 1; i <= N; i++) {
    sum += i;
}
```

Полностью разобрать первую итерацию: CMP готовит флаги, JG проверяет выход,
ADD прибавляет EAX к ECX, INC выбирает следующее число, JMP возвращает к CMP.
После ADD сумма уже изменилась, а счётчик ещё прежний. После INC счётчик
изменился, а сумма сохранилась. Последующие итерации пройти быстрее.

Для N=4 история EAX: 1→2→3→4→5; история ECX: 0→1→3→6→10. Конечный счётчик
равен 5: это первое число за границей. Результат находится в ECX, не в EAX.

При равенстве i=N ZF=1, поэтому JG не срабатывает и последнее число входит
в сумму. Выход: ZF=0 и SF=OF. ADD/INC меняют флаги; новый CMP готовит их
для следующего JG. При N=0 после MOV и первой проверки сразу выходим,
сумма 0, EAX=1.

Показать подсказку F6: signed8 −10, отсчёт от конца JMP, возврат к 401005.
Подвести к ошибке границы на следующем слайде.

## 13 — границы, трактовка и источник флагов, 6 минут

Три кадра: слева ошибка, справа исправление. Фрагменты принимаются ассемблером;
проблема проявляется в поведении. Это подготовленные примеры, угадывание не требуется.

### Кадр 1. Потерян последний элемент

Сумма пока 6, EAX=EBX=4. Сравнение даёт ZF=1, SF=OF=0.

```asm
; ошибка                 ; исправление
cmp eax, ebx             cmp eax, ebx
jge done                 jg done
```

JGE выходит при равенстве и теряет последнее слагаемое; получается 6.
JG оставляет равенство в теле; после добавления 4 получается 10.
Байты перехода меняются 7D→7F. Граница в C — i≤N; противоположное условие
выхода — i>N. Контрольные случаи: пустой диапазон, один элемент, последний элемент.

### Кадр 2. Выбрана другая трактовка числа

Знаковый максимум −1 и 1. EAX=FFFFFFFF, EBX=1, CF=0, SF=1, OF=0.

```asm
; ошибка                 ; исправление
cmp eax, ebx             cmp eax, ebx
jb use_b                 jl use_b
```

JB читает CF и пропускается; программа выбирает −1. JL читает SF/OF и
выбирает 1. Байты 72→7C. В регистре нет отметки signed; трактовку задаёт
выбранный переход. На экране используется структура веток максимума из слайда 9.

### Кадр 3. CMP больше не источник текущего ZF

EAX=EBX=7, ECX=0.

```asm
; ошибка                 ; исправление
cmp eax, ebx             inc ecx
inc ecx                  cmp eax, ebx
je equal                 je equal
```

Слева ZF=1 после CMP, затем ZF=0 после INC. JE пропускается, хотя операнды
сравнения равны. Справа последнее обновление — CMP, поэтому JE срабатывает.
Обе версии оставляют ECX=1; исправление меняет источник флагов перед переходом.
Перестановка безопасна здесь, потому что ECX не участвует в сравнении.

Не формулировать правило как запрет любой инструкции между CMP и Jcc:
MOV сохраняет флаги. Нужно проследить именно инструкции, меняющие нужные флаги.
Условный переход читает текущее состояние, а не историю сравнения.

Общий вывод: сначала условие выхода, затем трактовка чисел, затем источник флагов.

## 14 — четыре полных примера, 3 минуты

На слайде 14 — четыре карточки примеров и ссылка на следующий слайд.
Слайд 15 содержит отдельную пошаговую инструкцию работы из репозитория.
Полная студенческая инструкция: `examples/asm/README.md`.
Архив: `assets/examples/asm/control-examples.zip`. Исходники доступны отдельно.

| Программа | Что показывает | Ожидаемый код |
|---|---|---:|
| max.asm | CMP/JL и две ветки, максимум 7 и 3 | 7 |
| abs.asm | CMP/JGE и NEG, модуль −7 | 7 |
| sum.asm | Счётчик и накопитель, сумма 1…4 | 10 |
| for.asm | Инициализация отдельно, три итерации с +2 | 6 |

Все программы freestanding: `_start`, `.text`, регистры, алгоритм, `syscall`.
В конце результат копируется в EDI, в EAX записывается 60 и выполняется
sys_exit. Объяснить, почему сумму надо сохранить до изменения EAX.
Результат показываем через `$?`; это младшие 8 бит, примеры выбраны небольшими.
Программы не преобразуют число в строку и не печатают его в stdout.

## 15 — запуск из репозитория и чтение ELF, 6 минут

Пять шагов: открыть проект в VS Code → Docker → сборка и запуск →
дизассемблер → ELF и сырые байты.

### Подготовить до занятия

Запустить Docker Desktop/Engine, скачать Debian и установить NASM/binutils.
Интернет-загрузку не включать в время показа. Открыть корень репозитория
в VS Code. В терминале компьютера сначала перейти в папку исходников:

Windows PowerShell:

```powershell
Set-Location .\examples\asm
Get-ChildItem
```

macOS:

```sh
cd examples/asm
ls
```

Затем на обеих ОС выполнить одну и ту же команду:

```sh
docker run --name asm-examples --platform linux/amd64 -it --mount "type=bind,source=${PWD},target=/work" -w /work debian:bookworm-slim bash
```

Текущая папка уже examples/asm: дополнительный путь к PWD не добавляем.
--mount подключает её как /work; -w выбирает рабочую папку. На Windows
Docker Desktop использует Linux-контейнеры и WSL 2. Дальше команды идут
внутри Linux, включая NASM/ld и echo "$?". Повторный вход с компьютера:
`docker start -ai asm-examples`.

### Показать на занятии

1. Открыть sum.asm, отметить инициализацию EBX/ECX/EAX и блок завершения.
2. NASM создаёт .o, ld создаёт ELF. Запустить sum и сразу echo "$?": ожидаем 10.
3. Студенты вручную собирают, компонуют и запускают каждый пример; ожидаемые коды 7,7,10,6.
4. Через objdump -d -M intel найти CMP/JG/ADD/INC/JMP и SYSCall.
5. Прочитать одну строку: адрес в памяти → байты → инструкция.
6. Через readelf -h и -S найти архитектуру, точку входа, .text, Addr/Off/Size.
7. Через od посмотреть первые 64 байта файла: сигнатура 7F454C46 относится к ELF.
8. Через objcopy извлечь .text и через ndisasm -b64 разобрать сырой код.

Команды полностью приведены в README, на слайде есть копирование. Вывод на
слайде не имитирует настоящий терминал: команды выполняет преподаватель.

Файловое смещение в od, адрес секции в ELF и смещение в извлечённой .text
могут быть разными. NDISASM по умолчанию начинает с 0; для тех же адресов,
что в objdump, задают -o с Addr секции. Весь ELF содержит заголовки и таблицы,
поэтому для NDISASM берём извлечённую кодовую секцию.

Символы помогают найти `_start` и метки; комментарии исходника не восстанавливаются.
Дизассемблер может выбрать синоним JNL вместо JGE — машинный код тот же.

## Проверка и оставшиеся ограничения

Проверены NASM ELF64, байты коротких фрагментов, дизассемблирование объектного
файла, алгоритмы по собранным машинным байтам в ограниченной модели,
контрольные значения и поведение виджетов. Это не проверка исполнения Linux.
Docker daemon на машине подготовки не запущен, реальный запуск нужно проверить
перед занятием. Браузерная проверка file:// недоступна в используемом инструменте;
схемы просмотрены отдельно. Практическое задание на 80 минут пока не оформлено.
