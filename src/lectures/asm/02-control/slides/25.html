02 / практика · байты примеров

Найдите команды
в байтах каждого примера.

max.asm

39 D8 7C 04 по 0x100A — cmp и jl в else.

Ветки: 89 C1 по 0x100E и 89 D9 по 0x1012.

abs.asm

83 F8 00 7D 02 по 0x1005 — cmp с нулём и обход neg.

F9 FF FF FF по 0x1001 — то же −7, что на слайде 24.

sum.asm

7F 06 по 0x1011 — jg: цикл включает N.

EB F6 по 0x1017 — возврат jmp к проверке.

for.asm

83 C1 02 по 0x1013 — тело add ecx, 2.

7D 07 по 0x1011 — выход jge при i ≥ limit.

Как искать

Сборка со слайда 23 → readelf -S: найти Off секции .text → Hex Editor: Go To Offset → сверить с objdump -d -M intel.

Смещения здесь — для исходных примеров с .text по 0x1000. В своей сборке проверьте Off.

Показ: пройти четыре карточки и назвать, какая строка исходника прячется за каждой подписью байтов. Затем повторить в настоящем Hex Editor на файле, собранном на занятии.

Спросить: почему в max два разных байта ModR/M — 89 C1 и 89 D9? Ответ: последний байт выбирает источник: C1 копирует EAX, D9 — EBX; это две ветки if/else.

Спросить: чем подпись sum отличается от for? Ответ: байтом условия 7F (jg) против 7D (jge) и телом 01 C1 (add ecx,eax) против 83 C1 02 (add ecx,2) — граница и тело читаются прямо из байтов.

Граница: байты сверены с объектами NASM для исходных значений A=7, B=3, VALUE=−7, N=4 в sum и N=3 в for. Смещения 0x100x предполагают .text по 0x1000 после обычной компоновки ld из слайда 23. Даже без PIE это смещение не гарантируется: читайте Off в readelf. Для позиции внутри .text: файловое смещение = Off + позиция; адрес в памяти = Addr + позиция. Изменение констант, кода или кодировок может изменить байты и длины: сверяйте с дизассемблером своей сборки. Эти последовательности не являются универсальными сигнатурами конструкций C.
