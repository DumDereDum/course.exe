02 / разбор · jl и jb

«Меньше»: какая трактовка?

1 · На C
int32_t a = -1, b = 1;
if (a < b) { … }   // да
uint32_t u = 0xFFFFFFFF, v = 1;
if (u < v) { … }   // нет

Типы из <stdint.h> · EAX = FFFFFFFF · EBX = 1

2 · На NASM
; Два варианта после CMP
cmp eax, ebx
jl less    ; SF ≠ OF

; вместо JL для unsigned:
jb below   ; CF = 1

Один CMP, те же флаги. jl: −1 < 1 — да. jb: 4294967295 < 1 — нет.

Связь: слайд 10 показал, что биты FFFFFFFF — это и 4294967295, и −1. Здесь решаем, какой смысл проверяем, выбором перехода.

Пройти три блока: на C условие выглядит одинаково — различие в трактовке типов; инструкции различаются только байтом 7C/72; логика — разные пары флагов.

Спросить: какой переход выбрать для счётчика до миллиона? Ответ: зависит от типа: int32_t — jl/jge, uint32_t — jb/jae. В этом положительном диапазоне оба варианта дают одинаковый ответ; диапазон сам по себе не определяет тип. C-фрагменты используют типы из stdint.h и не смешивают signed с unsigned в одном сравнении. Строка jb заменяет jl, а не исполняется следом за ним; less/below обозначают продолжение соответствующей ветки.

Далее: слайд 12 выполняет оба перехода на одном и том же CMP с подсветкой SF/OF или CF и маршрутами ECX=1/0.
