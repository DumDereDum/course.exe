02 / пятый пример · вывод текста

Печатаем строку из памяти.

Данные · фрагмент text.asm
section .rodata
msg: db "Hello from the ASM lab"
     db 10
len equ $ - msg

db задаёт байты. 10 в decimal = 0A в hex: перевод строки LF.

Linux x86-64 · системный вызов
mov eax, 1
mov edi, 1
lea rsi, [rel msg]
mov edx, len
syscall

RAX = write · RDI = stdout
RSI = адрес · RDX = длина в байтах.

Внутри Linux · ручная сборка
mkdir -p build
nasm -f elf64 text.asm \
  -o build/text.o
ld -o build/text build/text.o
Сохранённый пример · команда и вывод
$ ./build/text
Hello from the ASM lab
$ echo "$?"
0

Текст и код завершения — два разных результата. В полном исходнике CMP/JNE проверяют запись 23 байт.

Полный text.asm ↓Как буква становится байтом →

Сказать: раньше показывали число через код завершения. Теперь WRITE отправляет настоящие байты в stdout; успешный код завершения — 0. Исходник целиком доступен по ссылке и в архиве. Здесь показаны фрагменты: db строки и db 10 разделены для компоновки, в исходнике это одна директива с теми же байтами.

Регистры: для Linux x86-64 RAX=1 — write, RDI=1 — файловый дескриптор stdout, RSI — адрес буфера, RDX=23 — размер. LEA загружает адрес msg, а не первый байт строки. rel задаёт адресацию относительно RIP; метка msg не является инструкцией. .rodata — данные, .text — код. Эти номера вызовов относятся к Linux x86-64.

Спросить: нужен ли нулевой байт в конце? Ответ: для write нет, размер задан явно. LF — отдельный байт 0A. Почему после write проверяем RAX? Это число записанных байтов либо отрицательный код ошибки. CMP/JNE ведут к выходу 1, если записаны не все 23 байта. Повтор короткой записи этот небольшой пример не реализует.

Показ: два подготовленных кадра; затем собрать и запустить в настоящем терминале. До занятия инструменты должны быть готовы. Реальный запуск в Docker с NASM 2.16.01 и ld 2.40 проверен: stdout содержит ровно 23 байта, exit=0; при закрытом stdout — exit=1. Команды слайд сам не исполняет. Пробел — кадр, Shift+пробел — назад, R — сброс. Около 5 минут.
