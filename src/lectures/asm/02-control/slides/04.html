02 / логика условного перехода

Условный переход
читает флаги, а не сравнивает.

Шаг 1 · Сравнение ставит флаги

cmp и test

CMP — вычитание, TEST — побитовое AND. Результат нужен только для флагов; операнды сохраняются.

Шаг 2 · Переход выбирает адрес

je, jl, jb…

Проверяют одно условие по флагам. Условие верно — RIP прыгает на метку; неверно — выполнение идёт дальше. Флаги не трогают.

Шаг 3 · Байт кодирует условие

Короткая форма: 7x + rel8

74 — je, 7C — jl, 72 — jb. Второй байт: −128…127 байт от адреса после перехода.

Формула перехода

jl: SF ≠ OF. После cmp a, b это знаковое «a меньше b». Иначе — следующая инструкция.

Переход читает текущие флаги, а не «помнит» сравнение.

Сказать: вся конструкция if — это три роли: кто выставляет флаги (cmp, test), кто их проверяет (условный переход) и куда прыгает (метка). Инструкция перехода сама числа не сравнивает.

Спросить: меняет ли mov флаги? Ответ: нет, поэтому между cmp и переходом mov безопасен. Какая инструкция между ними сломает логику? Ответ: любая, меняющая нужный флаг: inc, add, другая cmp.

Связь: дальше на слайде 05 — каталог всех переходов с условиями по флагам, затем на слайде 06 разбор первого примера по блокам.

Граница: CMP меняет ZF/SF/CF/OF/AF/PF; TEST устанавливает ZF/SF/PF по AND, сбрасывает CF/OF, AF не определён. Это не все биты RFLAGS. JL означает знаковое «меньше» именно после сравнения нужных операндов. Показана короткая форма Jcc: 7x и знаковое rel8; near-форма с большим диапазоном в x86-64 — 0F 8x и rel32. Смещение всегда отсчитывается от конца инструкции. Остальные условия, включая JO/JS/JP, здесь не разбираем.
