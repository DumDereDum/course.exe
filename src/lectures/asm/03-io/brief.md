# Лекция 3 — ввод, вывод и числа

Аудитория: студенты после лекций 01–02 по x86-64, Linux и NASM. Знают регистры,
mov/add/sub, флаги, cmp/jcc, циклы, syscall write/exit, секции .text/.rodata/.data/.bss
и таблицу ASCII.

Цель: прочитать десятичное число из stdin, разобрать его, удвоить и напечатать
в stdout в формате `Result: N`.

Платформа: x86-64, Linux, NASM; Intel-синтаксис; freestanding, без libc.
Формат: около 30 минут объяснения + самостоятельная практика; 22 слайда.
Подача: слева команда, напротив — действие простыми словами; для инструкций
показаны машинные байты. Сначала отдельные действия, затем сохранённые трассы.
Новые инструкции не считаются известными: XOR, LEA, MOVZX, IMUL и DIV
объясняются до применения в полном маршруте.
Практика: домашнее задание `double.asm`, ТЗ — `assets/examples/asm/io/README.md`.

## Слайды

| Файл | Одна мысль | Приём |
|---|---|---|
| 01 | Программа читает строку, получает число и печатает результат | титул, демо `21 → Result: 42` |
| 02 | Буфер выделяется до ввода | построчно `.bss`, `inbuf: resb 32`, `.text`; директивы не исполняются |
| 03 | XOR с собой обнуляет регистр, но ещё не читает ввод | `31 C0`, EAX/RAX до и после; смысл комментария `; read` |
| 04 | read получает источник, адрес и предельную длину | напротив каждой строки — смысл EDI, LEA RSI и EDX |
| 05 | Только syscall запускает чтение; возвращается количество байтов | регистры до вызова, `32 31 0A` и RAX=3 после; команды и данные |
| 06 | Адрес и содержимое по адресу — разные вещи | LEA против MOVZX, `byte`, нулевое расширение |
| 07 | Перед разбором нужны указатель, нулевой накопитель и метка | подготовка на экране, а не только в заметках |
| 08 | LF завершает разбор до арифметики | построчно MOVZX, CMP и JE; флаг ZF и метка done |
| 09 | Из кода символа получаем значение цифры | SUB, ASCII: `0x32 − 0x30 = 2`; отличие `'0'` от 0 |
| 10 | Три операнда IMUL: куда, что, на сколько | `6B C0 0A`, EAX: 2 → 20; умножение на десять |
| 11 | Цифра добавляется, указатель сдвигается, цикл повторяется | ADD, INC RSI, JMP NEXT с объяснением напротив |
| 12 | Два прохода собирают число 21; третий видит LF | sequence из трёх сохранённых состояний; результаты по строкам |
| 13 | Удвоенное число ещё не является текстом | ADD EAX,EAX: 21 → 42; 0x2A против байтов `34 32` |
| 14 | Для печати нужны адрес, делитель и счётчик | LEA RDI, MOV EBX, XOR ECX; индексы буфера 0…4 |
| 15 | DIV делит EDX:EAX; частное и остаток расходятся по регистрам | XOR EDX перед каждым DIV; 42 / 10 → 4 и 2 |
| 16 | Из остатка получаем символ и записываем его в буфер | ADD DL,'0', DEC RDI, MOV byte [RDI],DL; адрес против значения |
| 17 | Цикл печати считает цифры и проверяет частное | INC ECX, TEST EAX,EAX, JNZ; ноль проходит тело один раз |
| 18 | Цифры 2 и 4 записываются справа налево | sequence из трёх состояний; EDX после ADD уже содержит ASCII-код |
| 19 | LF входит в длину; адрес и длина сохраняются перед syscall | MOV в память, MOV R8, LEA R9; почему нельзя оставить длину в RCX |
| 20 | Первый write печатает префикс | два кадра, все пять инструкций с пояснениями и байтами |
| 21 | Второй write печатает число, затем exit завершает процесс | три кадра; восстановление адреса/длины и построчный exit(0) |
| 22 | Пять блоков складываются в программу; контракт домашки | flow, прогоны, ссылки на скелет и ТЗ |

Темп: 01–05 — 6 минут; 06–12 — 9 минут; 13–19 — 9 минут;
20–22 — 6 минут. Подробные вопросы и дополнительные трассы можно переносить
в практику. В объяснении не выводить сразу весь цикл мелким шрифтом.
Номера 02–05 перераспределены при этой переработке: прежние большие примеры
разделены на отдельные объяснения; задание перенесено из 05 в 22.
Для адресов и коротких переходов показан формат кодировки: конкретное смещение
определяется расположением меток, остальные байты сверяются NASM.

## Границы модели

- Один read в буфер 32 байта; для учебных прогонов предполагаем успешное чтение всей строки с LF. Сам размер буфера не гарантирует полного чтения.
- Вход гарантированно корректен: 0…99, цифры и LF; отрицательные не нужны.
- Код линейный: без call/ret, push/pop и функций; цифры пишутся с конца буфера.
- Переполнение, мусор, повтор короткого чтения и частичная запись — за пределами задачи.
- `read` и `write` могут вернуть меньше запрошенного; модель упрощена.

## Домашнее задание

`double.asm`: вход 0…99, выход `Result: N` и LF, где N = 2 × вход, без ведущих нулей.
Сдаются исходник, шесть прогонов (0, 1, 7, 21, 49, 99) и отчёт по бинарю: префикс `Result: `,
блок `div`, буфер `.bss`. Полное ТЗ — `assets/examples/asm/io/README.md`, скелет —
`skeleton.asm`. Студентам раздаётся только скелет и ТЗ; готового решения в текущем дереве нет.
